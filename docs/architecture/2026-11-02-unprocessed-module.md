# 未处理模块验收

用户确认：视频、语音及对应整条帖子默认不处理；互动作品、工具入口、不支持文件也进入“未处理”。普通抓取失败仍留在异常数据。已处理的90条视频维持原归类（61条有效分析、29条AI垃圾）。本方案替代0.8.8将视频归垃圾的行为。

## 行为

左侧新增“未处理”，卡片、列表和详情显示具体原因，支持搜索、类型、平台与日期筛选；与每日精选、普通内容、异常和垃圾分开，收藏关系保留。默认跳过补正文、取字幕、分析和翻译。

识别各来源视频、Twitter直播/Spaces语音、音视频扩展名及RSS/Atom媒体附件。明确的互动应用、非文章页面及PDF/JSON/纯文本文件也归入。403、404及暂时网络错误继续作为可重试异常；语音工具首页仍是文章/工具页面，不误算为语音。

采集设置改为“视频与语音”，配置为 `runtime.collection.process_media=false`。旧Twitter字段在新字段缺失时兼容读取，新字段优先；旧接口保留，界面使用 `/api/collection/media-policy`。运行中拒绝更改，本轮恢复沿用策略快照，开启后不自动重跑旧记录。

继续使用单张contents表，兼容增加 `is_unprocessed`、`unprocessed_reason` 列，不重建表。API投影为 `processStatus=unprocessed`，跳过不计为新分析成功。幂等迁移只接收未完成或原规则排除记录，清除规则垃圾标签，保留ID、正文、日志、入库日期及个人状态，不覆盖人工判断或已有AI结果。

未处理使用独立查询，读取全部记录，不受通用内容流500条窗口限制，正常内容流也不会被未处理记录挤占。
