# 主流内容平台的反馈与利用信号调研

> 调研日期：2026-09-13
>
> 对应决策票：[研究主流内容平台的反馈与利用信号](https://github.com/benjamin-qhy/qiushui-airadar/issues/14)
>
> 证据范围：旧项目当前源码；平台官方帮助、官方说明、官方开发资料或官方源码。没有可靠官方证据的项目明确标为“未核验”。

## 结论

qiushui-airadar 推荐采用 **三档个人喜好 + 独立质量反馈 + 独立利用动作**：

```text
个人喜好：喜欢 / 一般 / 不喜欢
内容质量：垃圾（可附原因）
利用动作：收藏 / 做成卡片 / 做成视频 / 其他后续扩展
```

其中：

- “一般”是用户主动点出的明确中性反馈；**没有操作是未知，不能等同于一般或不喜欢**。
- “不喜欢”只表示“与我不合适”，用于调整个人相关度；不说明内容本身差。
- “垃圾”表示广告、引流壳、无实质内容等质量问题，用于调整内容自身价值和信源质量。
- 收藏、做卡片、做视频可以同时存在；它们是“准备怎样利用内容”，不是喜欢程度。

大多数平台没有逐内容的“喜欢 / 一般 / 不喜欢”三档：常见做法是喜欢与负反馈两个方向，再叠加观看、跳过、收藏、分享等多种行为。Netflix 是三按钮，但第三档是“特别喜欢”，不是中性“一般”。抖音提供“减少 / 默认 / 增加”三级偏好调节，但它面向内容类别，不是单条内容。因此，三档不是照搬平台，而是针对 qiushui-airadar 的单用户、稀疏标注场景做的选择。

## 一、旧项目已经有什么

以下源码来自本地旧项目 `/Users/qiushui/work/qiushui/qiushuiai-aicontnet-extract`，核验提交为 `c3a572c3ccc8594dc54f669aa42c0135cb09d8b8`；所引用文件与该提交一致。

### 1. 已实现的人工反馈

- `mark_fp`：把“被误选进来”的内容移出 Feed；可以填写备注和原因。
- `mark_fn`：把“被漏掉”的内容退回待处理阶段。
- `undo`：撤销反馈。
- `score_adjust`：人工修改总分，并保存旧分、新分和备注。
- “已优化”标记：运营者可标记某条反馈是否已经被用于规则优化。
- 已读：记录内容是否被打开阅读，但没有停留时长或阅读完成度。

证据：`src/web/routers/feedback.py:21-25,95-145`、`src/web/routers/items.py:457-508`、`src/schema.sql:118-132`。

旧模型的问题是：`mark_fp / mark_fn` 描述的是系统筛选对错，不等于用户真正的“喜欢 / 一般 / 不喜欢”；它无法区分“内容不错但我不关心”和“内容本身是广告垃圾”。

### 2. 已实现的收藏与内容利用线索

- 收藏支持分组、备注、多个标签；同一内容可以进不同收藏分组。
- 收藏预设标签已经包含“卡片”“短视频”“实操”“技巧”“资源”“认知”，以及不同发布账号和写作视角。这说明旧项目已经把“如何利用”混进收藏标签。
- 但是旧项目没有“做成卡片 / 做成视频”的独立动作、任务状态或完成记录；它们只是标签，无法区分计划中、制作中、已完成。
- 精选内容可导出成轻量笔记与原文两个 Markdown 文件，供下游内容 Agent 先筛选、再按需读取原文；笔记还保留不会被覆盖的人工批注区。这属于“交给下游继续加工”的已实现能力。

证据：`src/web/routers/favorites.py:79-89,138-216`、`src/schema.sql:134-154`、`ui/src/pages/Feed.tsx:88-104,545-558`、`docs/guidelines/ai-feed-export-spec.md:12-29,187-203`。

### 3. 旧项目曾规划但没有形成现行能力的信号

旧设计稿曾计划记录 👍、👎、留言、点击和停留时长，并用“高分但 👎 / 低分但 👍”找出评分偏差，再由人工确认规则调整和回测；源码现状并未实现通用的喜欢、点击、停留时长学习模型。不能把设计稿当成已上线功能。

证据：`docs/working/2026-05-25-spec4-feedback-learning.md:12-49,112-143`。

## 二、平台对比

“无中档”表示没有找到逐内容的明确“一般”按钮；不代表平台把未操作当成中性标签。

| 平台 | 逐内容显式反馈 | 明确中档 | 参与推荐的隐式或多动作信号 | 收藏 / 再利用 | 模型形态 |
| --- | --- | --- | --- | --- | --- |
| YouTube | 喜欢、点踩、不感兴趣、不推荐频道；还有满意度问卷 | 无 | 观看与搜索历史、订阅、观看多少、分享、评论等 | 稍后观看、播放列表；Clip 与 Shorts remix | 两向反馈 + 多信号 |
| X | 喜欢、不感兴趣该帖/话题；屏蔽、静音、举报是更强负向 | 无 | 关注、回复、转帖、引用、点击、媒体观看、停留、分享等 | 私密书签；书签还可用于 Spaces 内容队列 | 多动作概率分别预测后加权 |
| Reddit | Upvote、Downvote、少看此类；2026 年小范围实验增加可撤销的 X 式“不感兴趣” | 无 | 帖子票数与评论历史、访问和停留的社区、订阅、近期访问、个人投票 | Save，之后在 Saved 中查看 | 两向投票 + 个性化多信号 |
| Netflix | 特别喜欢、喜欢、不适合我 | **有三档，但不是中性档** | 开始观看、是否看完、观看时长、观看历史、最近行为等 | My List；部分内容可离线下载 | 三档显式评价 + 观看行为 |
| TikTok | 喜欢、不感兴趣；“不喜欢评论”只适用于评论，不是视频评价 | 无 | 看完或跳过、观看时长、分享、评论、关注、主页访问等 | Repost；Duet、Stitch 可把原视频用于再创作 | 两向反馈 + 多信号 |
| 抖音 | 喜欢、不感兴趣；类别偏好可调“减少 / 默认 / 增加” | 单条内容无；类别有三级 | 完播、播放时长、评论，以及搜索、点击、关注、收藏、浏览、下载、分享等 | 收藏、分享、下载；可合拍 | 单条两向 + 类别三级 + 多信号 |
| 小红书 | 官方资料可核验“赞过”和“收藏”；本次未找到可靠官方资料确认逐笔记负反馈如何进入推荐 | 未核验 | 官方资料确认存在个性化推荐，但本次未找到可靠官方资料完整披露逐笔记信号及权重 | 收藏及收藏专辑已核验 | **反馈模型未完整核验** |
| Bilibili | 点赞、点踩、不感兴趣 | 无 | 点击、播放、投币、收藏、关注、搜索、分享等；模型融合正负倾向并实时反馈 | 收藏；投币是平台特有的强支持动作 | 两向反馈 + 多信号 |

### YouTube

YouTube 官方把观看历史、搜索历史、订阅、喜欢、点踩、“不感兴趣”、“不推荐频道”和满意度问卷都列为推荐信号；也明确会观察用户是否选择观看、观看多少。[推荐系统说明](https://support.google.com/youtube/answer/16089387?hl=en) [推荐调节说明](https://support.google.com/youtube/answer/6342839?hl=en)

稍后观看和播放列表是“以后再看”的保存动作；Clip 可截取和分享片段，符合“从内容继续加工”的利用语义。[稍后观看](https://support.google.com/youtube/answer/56101?hl=en) [Clip](https://support.google.com/youtube/answer/10332730?hl=en)

### X

X 官方帮助把关注、喜欢、转帖、分享、回复、观看媒体等列为推荐信号，并提供“不感兴趣该帖 / 该话题”。[推荐说明](https://help.x.com/en/rules-and-policies/recommendations)

X 当前公开的 For You 算法源码进一步表明，它不是训练一个“喜欢分”，而是分别预测喜欢、回复、转帖、点击、视频观看、停留、关注作者、不感兴趣、屏蔽、静音、举报等动作概率，再按权重合成排序分。[X 官方算法源码](https://github.com/xai-org/x-algorithm/blob/main/README.md#scoring-and-ranking)

书签是私密保存动作，还可以用来组织 Spaces 中准备分享的帖子。[书签说明](https://help.x.com/en/using-x/bookmarks)

### Reddit

Reddit 官方说明将帖子票数、评论历史、用户 Upvote/Downvote、在社区停留时间、最近访问、订阅和“少看此类”等一起用于个性化排序。[推荐说明](https://support.reddithelp.com/hc/en-us/articles/23511859482388-Reddit-s-Approach-to-Content-Recommendations)

截至调研日，Reddit 正在小范围测试一个可撤销的 X 图标：它既隐藏帖子，也告诉推荐系统以后少显示此类内容。这说明“隐藏”和“调整偏好”是两个应该明确区分的语义。[2026-08-12 官方更新](https://support.reddithelp.com/hc/en-us/articles/52393330268436-Changelog-August-12-2026)

Save 用于保存以后想回来看的帖子。[保存说明](https://support.reddithelp.com/hc/en-us/articles/205243605-How-do-I-save-a-post-and-where-does-it-get-saved)

### Netflix

Netflix 是本次唯一明确提供三档逐内容评价的平台：特别喜欢、喜欢、不适合我；这里没有中性“一般”，而是把正反馈拆成普通正向和强正向。[评价说明](https://help.netflix.com/en/node/9898)

Netflix 还会使用观看历史、开始观看、是否看完、观看时长和行为新旧等信号持续更新推荐。[推荐系统说明](https://help.netflix.com/en/node/100639)

My List 是独立的待看清单，不等同于喜欢评分。[My List](https://help.netflix.com/en/node/10523)

### TikTok

TikTok 的逐视频显式反馈主要是喜欢与“不感兴趣”；官方同时列出看完或跳过、观看时长、分享、评论、关注等信号，并指出用户互动通常比设备等信息权重更高。[推荐说明](https://support.tiktok.com/en/using-tiktok/exploring-videos/how-tiktok-recommends-content)

Repost 是把感兴趣的视频分享给朋友和社区；Stitch 可以选用原视频的一部分继续创作。两者都不是“喜欢”的同义词。[Repost](https://support.tiktok.com/en/using-tiktok/exploring-videos/repost) [Stitch](https://support.tiktok.com/en/using-tiktok/creating-videos/stitch-settings)

### 抖音

抖音官方算法说明指出，点赞、收藏、转发、评论等会进入排序，系统还会保留探索维度，避免内容过度单一。[算法说明](https://trust.douyin.com/algorithm/)

### 小红书

小红书官方深链资料能确认“赞和收藏页”、个人收藏页以及收藏专辑的存在。[官方深链说明](https://pages.xiaohongshu.com/activity/deeplink)

官方资料也能确认有个性化推荐开关。[热议话题规则](https://fe.xiaohongshu.com/ditto/vincent/b9ca419956094c3aafaa7c2354aff1c8?fullscreen=true&naviHidden=yes&source=wowcard) 但本次没有找到可靠官方帮助或公开源码，能够完整确认“逐笔记不感兴趣”的产品语义、逐笔记隐式行为如何进入推荐，以及相对权重；这些部分标为 **未核验**，不使用自媒体文章补齐。

### Bilibili

Bilibili 官方推荐算法说明最完整：点击、播放、点赞、投币、收藏、关注、搜索、分享、点踩、不感兴趣都会进入用户特征和融合排序，并由后续行为实时反馈给模型。[推荐算法说明](https://www.bilibili.com/blackboard/activity-gPIvOmhxbh.html)

## 三、为什么 qiushui-airadar 仍应采用三档个人喜好

### 平台为什么常用两向反馈

大型平台有海量隐式行为：用户看没看、看多久、是否跳过、是否搜索、是否复看，都可以帮助系统推测中间状态。多放一个“一般”按钮，通常只会增加操作成本。

### qiushui-airadar 为什么不同

qiushui-airadar 初期只有一位用户，而且每天的显式反馈远少于大平台。若只设“喜欢 / 不喜欢”，会有两个问题：

1. “没点按钮”可能是没看、忘记点、暂时没时间或无法判断，语义不可靠。
2. “不讨厌但也不值得多推荐”的边界内容，只能被迫归到喜欢或不喜欢，污染画像。

主动点出的“一般”可以提供可靠的分界样本：内容可以继续留在库里，但系统不应该因此强化或压低同类主题。建议训练语义为：

| 用户选择 | 机器含义 | 主要影响 |
| --- | --- | --- |
| 喜欢 | 明确正样本 | 提升相似主题、来源、形式的个人相关度 |
| 一般 | 明确中性样本 | 校准分界，不奖不罚；用于区分“看过但无明显偏好”和“未知” |
| 不喜欢 | 明确负样本 | 降低相似主题、来源、形式的个人相关度 |
| 未反馈 | 未知 | 不直接作为正负样本 |

因此推荐 **三档**，但不是把所有行为压成 `+1 / 0 / -1` 后就结束。平台共同经验更重要的一点是：保留多个动作的原始语义，再按不同目标加权。

## 四、统一但可扩展的反馈语义

### 1. 三条独立信号线

```text
内容本身好不好 ── 质量反馈 ──────> 内容价值、垃圾识别、信源质量
是否适合我 ────── 个人喜好 ──────> 个人相关度、画像更新
我准备用它做什么 ─ 利用动作 ────> 内容生产队列、可利用性画像
```

一条内容可以同时是：内容质量高、个人感觉一般、但值得做成卡片。三条线不能互相覆盖。

### 2. 建议的首期语义

| 维度 | 首期值 | 是否互斥 | 建议说明 |
| --- | --- | --- | --- |
| `preference` | `like` / `neutral` / `dislike` | 是 | 页面文案为“喜欢 / 一般 / 不喜欢”；同一时刻保留一个当前值，但修改历史要保留 |
| `quality` | `garbage` | 否 | 可撤销；可附广告、引流壳、无实质内容等原因；后续可扩展其他质量问题 |
| `usage` | `bookmark` / `create_card` / `create_video` | 否 | 页面文案为“收藏 / 做成卡片 / 做成视频”；同一内容可多选 |

扩展利用方式时新增稳定代码，不把自由文字直接变成核心枚举。后续候选包括 `write_article`、`share`、`apply_to_project`；是否进入首期由后续产品票决定。

“做成卡片”和“做成视频”还应有独立进度（至少计划中 / 已完成 / 已取消），否则按钮只能表达一次点击，无法成为可靠的内容生产清单。这个进度模型属于后续实现决策，本票只确认语义边界。

### 3. 原因标签

原因是对主反馈的解释，不应替代主反馈。建议先保留少量稳定标签：

- 不喜欢：主题无关、已经知道、太浅、太长、形式不合适、来源不合适。
- 垃圾：广告推广、纯引流、无实质内容、标题党、重复搬运。
- 一般和喜欢也允许备注，便于画像更新时理解“为什么”。

## 五、这些信号怎样用于后期推荐与筛选质量

### 1. 外部互动数据先判断“大家是否认可”，不能直接代表“我喜欢”

各来源能提供的数据统一成浏览、点赞、评论、转发、收藏等可空字段；没有的数据保持 `null`，不能写成 0。使用时还要按平台、内容形式、信源规模和发布时间归一化，并优先看增长量/增长率，避免大账号和旧内容天然占优。

外部互动主要进入 **内容价值** 的辅助特征，不直接写入个人相关度。否则“全网热门但与你无关”的内容会被误推到最高级。

### 2. 个人显式反馈校准“与我相关度”

- 喜欢 / 一般 / 不喜欢用于训练或调整个人相关度。
- 每次画像更新都应保留原始反馈、当时画像版本和评分版本。
- 系统只能提出画像调整草案并回测；按照已确认原则，由用户确认后才生效。

### 3. 垃圾反馈校准内容质量和信源

- 人工“垃圾”是强质量负样本；AI 只能标“疑似垃圾”，两者不能混为同一事实。
- 同一信源反复产生垃圾，可以降低信源质量先验并提醒人工检查，但不应自动封禁信源。
- 垃圾内容仍留在统一内容库，用于复核、回测和防止重复抓取。

### 4. 利用动作是更具体的价值信号

- 收藏：说明以后还想回来，偏向长期价值。
- 做成卡片：说明信息结构适合提炼为短图文。
- 做成视频：说明题材有表达、演示或传播潜力。

这些动作可作为个人相关度与“可利用性”的强正向特征，但不能自动等同于喜欢。例如，为了研究竞品而收藏一篇自己不认同的文章是合理的。

### 5. 不把“没操作”当负反馈

打开、停留、滚动、点击原文等隐式信号可以辅助排序，但噪声大，只应低权重使用。尤其“没收藏 / 没反馈”可能只是没有时间，不能直接当作不喜欢。若未来记录停留时长，也应允许关闭，并区分页面在前台与后台。

## 六、给领域建模票的建议答案

1. 人工反馈至少拆成 `个人喜好`、`内容质量`、`利用动作` 三组。
2. 个人喜好采用“喜欢 / 一般 / 不喜欢”三档；未反馈保持未知。
3. “垃圾”属于内容质量，不属于“不喜欢”的更强档位；两者可以同时存在并都可撤销。
4. 利用动作首期采用“收藏 / 做成卡片 / 做成视频”，允许多选；后续新增方式不改变已有数据含义。
5. 外部点赞、评论、转发、收藏等是来源快照和内容价值特征，不是用户个人反馈；字段缺失为 `null`。
6. 所有反馈与利用动作保留事件历史，同时提供一个当前结果用于页面查询；具体存储方案留给架构票决定。
